# 협곡 기록소

와일드 리프트 비정상 플레이(맵핵·어뷰징·고의 트롤) 제보 사이트 프로토타입입니다.

## 실행 방법

빌드 도구가 필요 없습니다. `index.html`을 그냥 브라우저로 열면 됩니다.

- 로컬에서 확인: `index.html`을 더블클릭하거나, VS Code의 Live Server 확장으로 열기
- GitHub Pages로 배포: 이 폴더를 저장소에 업로드한 뒤 **Settings → Pages → Branch: main → Save**
  하면 `https://<계정명>.github.io/<저장소명>/` 주소로 바로 접속됩니다.

## 관리자 기능 스위치

관리자 페이지의 `기능 설정` 탭에서 디버깅 중인 기능을 개별적으로 켜거나 끌 수 있습니다.

- 공개 명단
- 제보 제출
- 증거 사진 첨부 및 필수 여부
- 로그인과 회원가입
- 제보 신뢰도 평가
- 제보자 게임 닉네임 공개

설정은 현재 브라우저의 `localStorage`에 저장됩니다. 백엔드 연결 전까지는 방문자별로 설정이 다르게 보일 수 있습니다.

### 테스트 도구

관리자 페이지의 `테스트 도구` 탭에서 공개·대기·반려 상태의 샘플 제보와 인증·인증 대기 계정을 생성할 수 있습니다.

- 인증 샘플 계정: `demo_approved`
- 비밀번호: `demo1234`
- 샘플 데이터만 삭제
- 기능 설정 기본값 복원
- 전체 `wr-` 로컬 데이터 초기화

### 1. 데이터가 방문자의 브라우저 안에만 저장됩니다

이 프로젝트는 `localStorage`로 데이터를 저장합니다. **A의 브라우저에 올라온 제보나 계정은
B의 브라우저에 전혀 보이지 않습니다.** 지금 상태로는 "여러 사람이 같이 보는 사이트"가 아니라
"내 브라우저 안에서만 도는 데모"입니다.

실제로 사람들끼리 데이터를 공유하려면 서버(백엔드)가 필요합니다. 추천 경로:

- **Supabase** (Postgres + 인증 + 스토리지를 무료로 시작 가능) 가 가장 빠른 선택지입니다.
- `app.jsx` 안의 `store` 객체 하나만 Supabase 클라이언트 호출로 바꾸면, 나머지 UI 코드는
  거의 그대로 재사용할 수 있도록 설계해뒀습니다.

### 2. 비밀번호 보관이 프로덕션 수준이 아닙니다

`hashPass()`가 브라우저에서 해시를 계산해서 localStorage에 저장합니다. 서버 인증이 아니므로
실제 서비스에는 절대 이대로 쓰면 안 됩니다. Supabase Auth, Firebase Auth 같은 정식 인증
시스템으로 교체가 필요합니다.

### 3. 게임 계정 인증은 라이엇 공식 API 대조가 아닙니다

회원가입 시 게임 닉네임 + 스크린샷을 받아 운영자가 눈으로 확인하고 승인하는 방식입니다.
자동화된 본인 인증이 아니라서 위조 스크린샷을 걸러내지 못하고, 한 사람이 여러 계정을 만드는
것도 완전히는 막지 못합니다. 진짜 방지가 필요하면 Riot Sign-On(RSO) 같은 공식 OAuth
연동을 라이엇 개발자 포털에서 신청해야 합니다.

### 4. 명예훼손 관련 법적 리스크

한국은 사실을 적시해도 명예훼손이 성립할 수 있습니다(형법 307조 1항). 이 프로젝트는

- 제보 즉시 비공개 → 운영자 승인 후에만 공개
- 실명·연락처·SNS 등 개인정보 자동 차단
- "확정된 사실이 아니라 제보자의 주장"이라는 문구 상시 노출

같은 완화 장치를 갖추고 있지만, 법적 위험을 없애주는 것은 아닙니다. 실제 운영 전에
변호사 상담을 다시 권장합니다.

### 5. 관리자 비밀번호

지금 관리자 페이지 비밀번호는 코드에 하드코딩된 `admin`입니다. **공개 저장소에 올리기 전에
반드시 바꾸세요.** `app.jsx`에서 `pass === "admin"` 부분을 검색하면 나옵니다. (이것도
서버 인증 없이는 근본적으로 안전할 수 없는 방식이라, 실서비스 전환 시 가장 먼저 손봐야 할
부분입니다.)

## 파일 구성

```
index.html   ─ 페이지 진입점, CDN에서 React/Tailwind/Babel 불러옴
app.jsx      ─ 전체 애플리케이션 로직 (컴포넌트, 저장소, 검증 규칙 등)
```

Babel을 브라우저에서 바로 돌려 JSX를 변환하는 방식이라 빌드 단계가 없습니다. 트래픽이 늘거나
성능이 중요해지면 Vite 같은 도구로 사전 빌드하는 구조로 옮기는 걸 권장합니다.
